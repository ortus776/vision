# Архитектура инференса и mock-отрисовка — 02.10.2026

Подготовлен путь `Frame → RGB/NCHW letterbox → Model → Candidate → ROI Detection → renderer`. Пользователь готовит модель самостоятельно; архитектура пока использует `MockModel`, который на каждом обработанном кадре генерирует случайную рамку. Настоящий ONNX runtime и декодер конкретного формата выходов не подключены.

## Реализовано

- `ModelSpec` и заменяемый интерфейс `Model`; общая фабрика `src/app/inference_model.hpp`.
- RGB float32 /255, bilinear half-pixel resize, letterbox с padding 114 и реальными масштабами по двум осям.
- Обратные координаты, clip, confidence, class-aware NMS, ограничение количества кандидатов и результатов.
- Один inference worker, один заменяемый ожидающий кадр и один результат; FPS, TTL от времени захвата, поколение и ревизия паузы; передача исключений владельцу.
- `--live`: UI и отдельные потоки источника/модели; фокус, геометрия, восстановление, F8/F9, очистка overlay.
- Win32 layered overlay и общий программный BGRA renderer для рамок и точек. Тот же renderer используется в PNG-проверке.
- `--synthetic-source` для live-проверки отрисовки поверх неподвижного окна; обычный live использует DXGI.
- `--inference-demo` для создания PNG и координат без GUI, в отдельном уникальном каталоге.

Layered окно использует `WS_EX_TRANSPARENT` и `WS_EX_NOACTIVATE`; пропуск мыши соответствует [описанию layered windows Microsoft](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features). Прозрачная BGRA-поверхность передаётся через [UpdateLayeredWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow). Исключение из захвата требует [WDA_EXCLUDEFROMCAPTURE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity), поддерживаемого с Windows 10 2004; ошибка установки явно завершает запуск.

## Проверки

Сборка MSVC с `/W4 /permissive- /Zc:__cplusplus /utf-8` выполнена напрямую через `cl` в пределах workspace, поскольку в текущей среде MSBuild FileTracker ранее возвращал отказ доступа. CMake configure/generate выполнен; стандартные presets сохранены для обычного пользовательского PowerShell.

Unit-проверки покрывают известные значения цветовых каналов и bilinear interpolation, padding, округлённые масштабы, обратный пересчёт, NMS по классам, invalid/NaN значения, границы, прозрачность и точку. Конкурентные тесты с блокируемой моделью проверяют замену 98 из 99 ожидающих кадров, отсутствие публикации старого результата при смене поколения и паузе/возобновлении, истечение TTL во время обработки и передачу ошибки модели.

Интеграционная проверка запускает настоящий EXE, создаёт по три PNG в режимах рамки и точки, проверяет CRC, восстанавливает PNG scanlines и сравнивает каждый зелёный пиксель с ожидаемой геометрией из `detections.jsonl`. Предыдущие проверки сборщика и валидатора включены в CTest.

Итоговый `ctest --preset windows-msvc-release`: **5/5, ошибок нет**. Обновлены приложение и тестовые EXE в `build/windows-msvc/Release`; предыдущие бинарники сохранены в `build/before-inference`. Дополнительно созданы и проверены пять демонстрационных кадров в `build/inference-preview/inference_demo_1790955415724_0`; первый PNG осмотрен визуально, рамка соответствует координатам manifest.

## Ограничения и продолжение

Живая проверка прозрачности, кликов и захвата overlay в этой среде не выполнена: доступ процесса из sandbox к рабочему столу ограничен; предыдущие попытки Computer Use были отклонены автоматической проверкой доступа. PNG-тест подтверждает отрисовку и координаты, но не заменяет GUI-проверку и проверку игры.

При подготовке модели нужно реализовать адаптер `Model`, зафиксировать его вход/классы и декодировать сырые выходы в `Candidate[]` с XYXY в пикселях входного тензора. Сессию runtime следует создать один раз и использовать в worker. Затем подключить адаптер в общей фабрике, добавить выбор backend в CLI и сравнение тензоров/выходов с Python. Режимы файлового инференса `image`, `replay` и реальные замеры производительности остаются следующими задачами.
